# 落地页视觉与交互说明

本文记录落地页的设计决策，改动前先看这里，避免越改越像通用模板。

## 设计取向

前台面向**要花钱买接口的开发者**。他们的判断路径是：
「这站靠不靠谱」→「支持我要的模型吗」→「多少钱」→「接起来麻烦吗」。
整页按这个顺序排：一屏之内给结论，细节再往下展开。

视觉上走**编辑式排版**：靠字号对比、留白与细线分区，不靠卡片堆叠和阴影。
参考的是产品文档页，而不是常见的 SaaS 营销页。

## 版式

```
┌──────────────────────────────────────┐
│ 页头：品牌 · 锚点导航 · 主按钮          │  sticky，半透明磨砂
├──────────────────────────────────────┤
│ 首屏                                    │
│  大标题（随视口缩放）  │  接入地址卡      │  两栏，1.35 : 1
│  三行事实点            │                 │
├──────────────────────────────────────┤
│ 为什么用中转站：2×2 网格，细线分隔        │  不用卡片，纯线条
├──────────────────────────────────────┤
│ 支持模型：按厂商分组的表格                │  表格嵌在卡片里
├──────────────────────────────────────┤
│ 价格：左规则 / 右算账示例                 │  算账示例是重点
├──────────────────────────────────────┤
│ 接入步骤：1 2 3 竖排                     │  这里确实是顺序，才用编号
├──────────────────────────────────────┤
│ 深色行动区：左行动入口 / 右可复制地址      │  全页唯一强对比
├──────────────────────────────────────┤
│ 页脚                                     │
└──────────────────────────────────────┘
```

## 关键决策与理由

**首屏不放没有依据的数据。** 不写「已服务 10 万开发者」这类数字，除非真能量出来。
三行事实点只讲产品本身：2 套协议 / 1 个密钥 / 按量计费。

**接入地址在首屏就给。** 开发者最先想知道的就是「地址长什么样」，
所以首屏右侧直接放卡片，不用滚到底才看到。

**「算一笔账」比列价格表有用。** 按量计费最反直觉的是「一次调用到底多少钱」，
所以直接拿一次带 12000 token 上下文、回答 800 token 的请求，把账算给人看。
算法在 `billing.ts`，有单测。

**深色只用一次。** 收尾行动区是全页唯一的深色块，把注意力收在「开始用」上。
其他地方一律暖白，避免深色块把页面切碎。

**编号只用在真正有顺序的地方。** 接入步骤是 1→2→3 的流程，用编号；
卖点彼此没有顺序关系，就用细线分隔的网格，不编号。

**圆角分级。** 小元素 6px、卡片 14px、大面板 20px，而不是一个圆角用到底。

## 无障碍与响应式

- 键盘焦点可见（琥珀金描边），页头带「跳到主要内容」链接；
- 尊重系统的「减少动态效果」设置（`prefers-reduced-motion`）；
- 黄底一律配深色字，保证对比度；
- 断点：960px（首屏与深色区转单栏）、860px（导航收进下拉菜单）、
  760 / 640px（网格转单栏）。375px 宽度下实测无横向溢出。

## 已知取舍

- 表格在窄屏用横向滚动（`scroll={{ x: 520 }}`），没做卡片式重排 ——
  模型表只有三列，滚动比重排更省事。
- 字体用 Instrument Sans（西文）+ JetBrains Mono（等宽）+ 系统中文字体。
  中文没有单独引入字体包，走系统字体以保证加载速度；若以后要统一中文观感，
  再考虑引入思源黑体的子集。
